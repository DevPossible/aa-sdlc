# Feature-page and snapshot tooling

Requirements: [F-093](knowledge/Requirements/framework/feature-tooling.md).
Backport scope and evidence: [approved change record](feature-tooling-backport.md).

The helpers ship under `scripts/aa-sdlc/` when `aa init` or `aa update` installs a
project. Authoritative sources are in `src/aa-sdlc/scripts/`. PowerShell 7.4 or newer
is required by the module manifests; the snapshot command also requires
`powershell-yaml`, already installed by this framework's `initialize.ps1`.
Both module manifests start at the ported module version `0.1.2`, independently
of the framework release version. `AaFeatures.psd1` exports the existing four
conversion/checksum/provenance functions. `ConfluenceFeatureImport.psd1` exports
only `ConvertFrom-ConfluenceFeatureSnapshot`. Direct `.psm1` imports still work.

On another project machine without the YAML module, install that declared command
dependency with `Install-Module powershell-yaml -Scope CurrentUser` before using
the snapshot command. The public module API can instead receive the configured
values directly and does not require `powershell-yaml`.

## Feature pages and synchronization

The converter accepts canonical ATX headings, MCP-exported Setext headings and the
export format with empty table headers. It preserves scenario IDs, status, exact
steps, Background, outline examples and escaped pipes. Only Approved scenarios
generate output. A valid Draft-only or Retired-only page generates nothing.

Malformed separators, inconsistent widths, invalid or duplicate identities,
duplicate metadata, invalid statuses/kinds/steps, missing outline examples and
unconsumed tables fail explicitly. Every scenario is validated before filtering.

`Sync-FeatureFiles.ps1` validates all source pages and destination names before
changing files. A missing Requirements folder, invalid page, duplicate destination
or unsafe portable filename aborts that batch, preserving existing generated bytes.
This prevalidation is not a filesystem transaction for a later disk failure.

## Offline Confluence snapshots

Acquire and review a permitted REST storage snapshot through the tools already in
scope. The importer makes no network calls, acquires no credentials and grants no
approval. The caller remains responsible for acquiring pages under the project's
authorized knowledge root, including when projects share a space.

The command reads a single project `aa.config.yaml`, defaulting to the working
directory. `-ConfigPath` selects an explicit file; it does not merge other scopes.
Existing fields supply the identity:

```yaml
version: 1
scope: project
conventions:
  knowledge:
    space: EXAMPLE
    url: https://docs.example.test/wiki/spaces/EXAMPLE
```

The space must match the snapshot exactly. The URL must be an HTTP(S) space URL
ending in `/spaces/<space>` without credentials, query, fragment or whitespace.
A trailing slash is accepted. Output provenance names that URL, page ID and
positive integer version. Invalid snapshot metadata and unsupported storage
markup fail before output is written. No Agent Possible URL or space is assumed.

```powershell
./scripts/aa-sdlc/Import-ConfluenceFeatureSnapshot.ps1 `
  -SnapshotPath reviewed-page.json -OutputPath features/example.feature `
  -ConfigPath aa.config.yaml

# Verify without writing.
./scripts/aa-sdlc/Import-ConfluenceFeatureSnapshot.ps1 `
  -SnapshotPath reviewed-page.json -OutputPath features/example.feature -Check
```

The public module function takes `-Json`, `-KnowledgeSpace` and `-KnowledgeUrl`
explicitly, so it needs no YAML parser. Storage tables, ordinary inline text,
supported links and simple preamble lists preserve their content. Recognized HTML
named references are converted one layer at a time; escaped markup stays text.
Unknown references, DTDs/external entities, macros, images, merged cells and
unsupported list/narrative structures are rejected rather than silently omitted.

The command refuses handwritten or edited destinations, another source page,
version downgrades and conflicting content at the same version. If approvals
disappear it retains existing output and requests reconciliation; it does not
create an empty acceptance file. Successful updates replace a temporary file in
the destination directory. `-Check` requires exact output after normalizing line
endings and leaves the destination untouched.

## Selected Approved scenarios

`ConvertFrom-FeaturePage`, `ConvertFrom-ConfluenceFeatureSnapshot` and the snapshot
command accept optional `-ScenarioId @('F-910-01', 'F-910-03')`. Omitting it retains
whole-page Approved output. An explicit selection must be nonempty, unique and
case-exact, and may name only Approved IDs. Full-source validation runs first;
output follows source order, with Background and examples preserved.

Selected output adds these comments inside its checksummed body:

```gherkin
# Selected scenario IDs: F-910-01 F-910-03
# Source Markdown checksum: sha256:<full Markdown hash>
```

The source checksum normalizes line endings only and covers unselected content.
A newer source version updates this binding even when selected steps do not change.
The snapshot command refuses malformed/duplicate projection metadata, same-version
source conflicts, and silent changes to selection membership, including adding or
removing selection. Use a new destination for a different projection. Caller ID
ordering may differ; output ordering follows the current source.

## Validation

`./test.ps1 -Tier unit` runs the original conversion tests, the two backported
regression catalogs, manifest/configuration tests and structural/provenance checks.
After `./build.ps1 -Lint`, `./test.ps1 -Tier integration` installs real embedded
helpers into a disposable project, imports/checks a snapshot, and verifies update
restoration without changing project configuration. Fixtures use no live account.
