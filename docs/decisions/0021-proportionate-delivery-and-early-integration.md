# 0021: Approve bounded work once and prove real integration early

**Date:** 2026-10-26 | **Status:** accepted | **Anchor:** [0.6.0 change record](../releases/0.6.0.md)

## Context

Agent Possible exercised the framework in a large implementation. Its commits
`1e5c1b68`, `1772e84a`, `134214b8` and `700a821c` removed repeated approval stops,
duplicate proof packaging and unnecessarily broad resource waits, then moved real
collaborator checks earlier. Its retrospective records more component reviews
without a new runnable outcome, late fixture/contract mistakes and substantive
defects found by independent review. This is field evidence for changing the loop,
not a measured claim of sustained throughput improvement.

## Options and decision

Adopt the general delivery rules in core. Keeping the local fork would preserve
contradictory installations; copying only its rendered skills would leave the
registry and generated consumers contradicting them. Removing acceptance checks
would discard useful defect detection. Richard authorized implementation, full
review, adjustments, release and local upgrade in this session.

One proportionate approved brief covers implementation through review within its
boundary. Explicit task-scoped commit permission persists; implementation alone
does not grant it. Local commits are checkpoints, not stakeholder acceptance.
Prove behavior at justified tiers, probe the real collaborator early, and reuse
valid independent evidence for its exact scope. Retain full-suite branch finish,
required independent acceptance, provenance, coverage, UAT and release controls.
Record unresolved failures without retrying them into acceptance. Protect the
current runnable outcome and coordinate actual shared resources.

## Consequences

This revises O-08, O-17, O-23 and O-26, and supersedes the automatic-delegation
wording of decision 0015: installed agents are capabilities, not authority.
In Review means a verified candidate ready for review, linked through a merge
request or an authorized local review record. State names remain mapped by the
project config. Task commit permission, delegation and external/release permission
are separate and revocable. Model selection and Agent Possible's runtime-specific
accounting, authority and installed-generation rules stay in that project.

The source registry, workflow, feature pages, skills, generated agents and website
must agree. Measure first working behavior, first real join, setup-invalidated runs,
waiting and newly executable user operations. Keep this policy concise enough that
its evidence record and preflight do not become another approval ceremony.
