# 0012: Guidance sets are installed once as shared files, not copied into every skill

**Date:** 2026-09-23 | **Status:** accepted | **Ticket:** none

## Context

Every skill carried the full text of each guidance set it cited, so the five `every-step`
rules appeared in 52 files and the twelve `code-change` rules in most of them: 36,531 of the
package's 74,472 skill words were guidance text, almost all of it repeated. Decision record 0011
found no other slack in the skills and named this as the one lever, on condition that it be a
design change with its own record rather than a compression. The user asked for it.

The reason for copying was that a skill reads whole to someone with no context (G-24, T-13).
That still holds: the reader must be told, in the skill, exactly where the shared text is.

## Options

- **A. A shared `aa-guidance` skill folder holding one file per guidance set, installed beside
  the step skills; each skill names the sets it reads with their location and keeps its own
  step-specific guidance inline.** Chosen.
- **B. Keep copying.** Correct and self-contained, at 28,000 repeated words that must be kept in
  step with the registry by a sync.
- **C. One shared file with every rule.** Forces a reader to load 48 rules to find the five that
  apply; the sets exist precisely to group what a step needs.

## Decision

Option A.

- Source: `src/aa-sdlc/skills/aa-guidance/SKILL.md` (hand-written, says what the folder is and
  that it is not a command) and `src/aa-sdlc/skills/aa-guidance/sets/<set-id>.md`, one per
  guidance set, generated by `scripts/Sync-SkillGuidance.ps1` from the set's YAML and
  `docs/guidance.md`. The set file carries the set's purpose and each rule verbatim.
- Skill text: the Guidance section lists the sets the step cites, each with its purpose and the
  path `src/aa-sdlc/skills/aa-guidance/sets/<set-id>.md`, then `*For this step:*` with the
  step's own guidance ids verbatim and its inline guidance. Set rules no longer appear in the
  skill; `scripts/Test-SkillGuidance.ps1` fails if one does, if an own rule is missing or
  paraphrased, or if a set file differs from the registry.
- Install: the CLI copies the `aa-guidance` folder to `<scope>/skills/aa-guidance/` with no
  command, and rewrites the source path in every installed skill to the scope's path
  (`.claude/skills/aa-guidance/...` at project scope, `~/.claude/skills/aa-guidance/...` at
  user scope), so the path an agent reads resolves from wherever it runs. `aa-guidance` is a
  core name for update and stale removal.
- In this repository the commands read the source skills directly, and the source path
  resolves from the repository root, so nothing is rewritten here.

## Consequences

- The package's skill text drops by roughly 28,000 words; the set text exists once.
- A step invocation now reads one to three small set files instead of finding the rules inline.
  The rules an agent reads are the same; the reading is one tool call away.
- Editing `docs/guidance.md` or a set changes one generated file per set instead of 52 skills;
  the unit check still fails until the sync runs.
- Another target adapter must install `aa-guidance` beside its skills and rewrite the same path;
  section 6 of the design says so.
- The `aa-guidance` folder is a skill folder in shape only; it has no step, no command, and the
  structural validator treats it as the top-level exception it already allows.
